# 其他项目如何调用本项目

本项目是 CEK-TA 支持层。其他项目不应该复制本项目里的专业知识，而应该通过 `AGENTS.md`、Project Adapter、Skills、MCP/RAG 和可选 Plugin 来调用本项目能力。

## MCP 快速入口

如果外部项目只是想先验证“能不能查询 CEK-TA 正式知识库”，优先阅读：

[external_mcp_quickstart.md](./external_mcp_quickstart.md)

最小 smoke：

```powershell
$env:CEK_TA_ROOT = "替换为你的 CEK-TA 根目录"
cd $env:CEK_TA_ROOT
python codex-expert-kit/mcp/server.py --info
python codex-expert-kit/mcp/server.py --list-tools
python codex-expert-kit/mcp/server.py --call search_expert_knowledge --request-json "{\"query\":\"lookahead bias\",\"top_k\":3}"
```

业务项目接入 Codex MCP 时使用模板：

```text
codex-expert-kit/templates/codex_config_mcp.toml
```

模板默认 `enabled = false`。必须先完成 `--info`、`--list-tools` 和一次查询 smoke test，再在业务项目配置里改为 `enabled = true`。

MCP 调用边界：

```text
1. MCP 默认只读。
2. 查询正式 knowledge_items.json 聚合索引。
3. 候选知识不能作为默认指导。
4. reviewed/caveat_only 不等于 approved。
5. default guidance 和 hard gate 必须读取 review / machine_gate 字段。
```

## 接入目标

```text
业务项目只提供项目事实。
CEK-TA 提供通用专业知识、审计规则、Skill 工作流、RAG/MCP 检索和 Vue3 审计能力。
```

其他项目也可以把经过审计的专业知识倒灌回 CEK-TA，但必须遵守：

[知识倒灌与反哺规范.md](./知识倒灌与反哺规范.md)

## 推荐接入层级

| 层级 | 用途 | 适合阶段 |
| --- | --- | --- |
| Level 1: AGENTS.md | 告诉 Codex 当前项目如何引用 CEK-TA | 立即可用 |
| Level 2: Project Adapter | 声明项目类型、事实、字段、pipeline | 立即可用 |
| Level 3: Skills | 复用策略审计、回测审计、交易分析等工作流 | 第一版能力包后 |
| Level 4: MCP/RAG | 让 Codex 动态检索专业知识和来源 | 知识库跑通后 |
| Level 5: Plugin | 把 Skills、MCP、配置打包分发 | 长期标准化 |

## 运行时接入总流程

其他项目真实接入时，按下面顺序执行：

```text
1. 在业务项目创建或更新 AGENTS.md。
2. 在业务项目创建 docs/project_adapter.md。
3. 在 adapter 中声明项目事实、运行模式、字段映射、数据源、风险边界和 CEK-TA tool 权限。
4. 执行外部项目健康检查。
5. 如果需要知识检索，优先使用只读 MCP/RAG 工具。
6. 如果发现可复用经验，使用 contribution_from_project.md 生成 proposed 倒灌任务。
7. 把 proposed 任务提交到 CEK-TA contributions/proposed/，等待 CEK-TA 审计。
```

运行时必须输出：

```text
adapter_status
missing_fields
unsupported_modes
allowed_tools
blocked_tools
project_fact_boundary
knowledge_query_scope
contribution_entrypoint
healthcheck_result
```

## 接入契约

业务项目的 `docs/project_adapter.md` 必须覆盖：

```text
project_id

project_type
market
asset_classes
data_sources
strategy_types
runtime_modes
backtest_engine
execution_adapter
risk_scope
private_fields
allowed_cek_ta_tools
blocked_cek_ta_tools
knowledge_query_scope
contribution_policy
```

模板位置：

```text
codex-expert-kit/templates/project_adapter.md
```

关键边界：

```text
项目事实留在业务项目。
CEK-TA 只提供通用专业知识。
CEK-TA 默认只读。
CEK-TA 不能读取密钥、账户数据、原始订单。
CEK-TA 不能下单。
CEK-TA 不能直接写 approved 知识。
```

Codex 手册中的能力边界可以概括为：

```text
AGENTS.md: 放项目级持久规则和工作约定
Skills: 放可复用任务工作流
MCP: 给 Codex 提供外部工具和上下文
Plugin: 分发 Skills、MCP 配置和相关资源
```

## 方式 A: 最小接入

适合任何业务项目立即使用。

在业务项目根目录创建 `AGENTS.md`：

````md
# AGENTS.md

本项目调用 CEK-TA 支持层。

## CEK-TA Location

```text
替换为你的 CEK-TA 根目录，推荐通过 CEK_TA_ROOT 声明。
```

## 必须读取

开始交易、回测、模拟盘、实盘、LLM、RAG 相关任务前，先读取：

```text
$CEK_TA_ROOT/docs/index_tasks.md
$CEK_TA_ROOT/docs/需求框架.md
$CEK_TA_ROOT/docs/知识库采集与审计规范.md
```

## Project Adapter

adapter: kline_trend_strategy

## Enabled Domains

- quant_trading
- kline_strategy
- backtest_replay_simulation
- trade_analysis

## 本项目事实

1. 在这里填写本项目市场、周期、字段、pipeline、配置、运行命令。
2. 项目事实优先于 CEK-TA 通用知识。
3. 不允许把本项目私有字段写回 CEK-TA 通用知识。

## Hard Rules

1. 任何专业结论必须引用 CEK-TA 知识或联网来源。
2. 发现 CEK-TA 知识冲突时，必须标注冲突，不得强行合并。
3. 修改交易逻辑必须说明输入、输出、影响模块、验证指标和回滚方式。
````

使用方式：

```powershell
cd E:\your_project
codex
```

然后直接让 Codex 执行任务。Codex 会先读业务项目 `AGENTS.md`，再按里面的路径读取 CEK-TA 文档。

## 方式 D: Skills 复用

适合已经沉淀好 `codex-expert-kit/skills/*/SKILL.md` 之后。

Codex 会扫描仓库或用户目录中的 `.agents/skills`。业务项目可以把 CEK-TA Skills 暴露给 Codex。

推荐目录：

```text
your_project/
└── .agents/
    └── skills/
        ├── strategy-auditor/
        ├── backtest-reviewer/
        └── trade-quality-analyst/
```

Windows 本机可以用目录联接：

```powershell
New-Item -ItemType Directory -Path .agents -Force
New-Item -ItemType Junction -Path .agents\skills -Target "$env:CEK_TA_ROOT\codex-expert-kit\skills"
```

使用方式：

```text
请使用 $backtest-reviewer 审计这次回测结果
请使用 $trade-quality-analyst 分析这些交易记录
```

## 方式 E: MCP/RAG 调用

适合需要动态检索 CEK-TA 知识的项目。Phase 14+ 提供本地只读运行时入口：

```text
codex-expert-kit/mcp/server.py
```

完整短路径手册见：

[external_mcp_quickstart.md](./external_mcp_quickstart.md)

先在 CEK-TA 根目录做命令行 smoke：

```powershell
$env:CEK_TA_ROOT = "替换为你的 CEK-TA 根目录"
cd $env:CEK_TA_ROOT
python codex-expert-kit/mcp/server.py --info
python codex-expert-kit/mcp/server.py --list-tools
python codex-expert-kit/mcp/server.py --call search_expert_knowledge --request-json "{\"query\":\"lookahead bias\",\"top_k\":3}"
```

业务项目可以在 `.codex/config.toml` 中配置 CEK-TA MCP。初始必须保持 `enabled = false`：

```toml
[mcp_servers.cek_ta_knowledge]
command = "python"
args = ["替换为你的 CEK_TA_ROOT\\codex-expert-kit\\mcp\\server.py"]
startup_timeout_sec = 20
tool_timeout_sec = 60
enabled = false

[mcp_servers.cek_ta_knowledge.env]
CEK_TA_ROOT = "替换为你的 CEK-TA 根目录"
CEK_TA_MCP_MODE = "read_only"
CEK_TA_KNOWLEDGE_ITEMS_PATH = "替换为你的 CEK_TA_ROOT\\codex-expert-kit\\rag\\indexes\\knowledge_items.json"
```

只有当 `--info`、`--list-tools` 和一次 `search_expert_knowledge` 查询都通过后，业务项目才应改为 `enabled = true`。

路径移植规则：

```text
1. 上面的路径是示例，不是运行时代码应写死的路径。
2. 业务项目迁移到其他机器、Git submodule 或团队目录时，优先改 CEK_TA_ROOT。
3. CEK-TA 内部代码通过 codex-expert-kit/core/path_resolver.py 定位根目录。
4. 如果没有显式配置 CEK_TA_KNOWLEDGE_ITEMS_PATH，MCP 会通过 resolver 默认定位到 rag/indexes/knowledge_items.json。
5. 新增正式知识后，在 CEK-TA 根目录执行 `python codex-expert-kit/rag/scripts/build_knowledge_items_index.py` 重新生成索引。
```

Phase 21 之后，MCP 默认正式知识聚合索引是：

```text
codex-expert-kit/rag/indexes/knowledge_items.json
```

该文件由正式知识目录生成：

```text
codex-expert-kit/rag/knowledge/
```

新增或修改正式知识后，在 CEK-TA 项目内重新生成：

```powershell
python codex-expert-kit/rag/scripts/build_knowledge_items_index.py
```

Codex 可调用的工具：

```text
search_expert_knowledge()
get_knowledge_item()
get_conflict_audit()
get_source_profile()
list_kb_partitions()
browse_knowledge_tree()
```

只读权限边界：

```text
允许：检索知识、查看来源、查看冲突、查看分区。
禁止：读取密钥、读取账户数据、下单、批准知识、写入 approved 知识。
```

本地调试示例：

```powershell
python codex-expert-kit/mcp/server.py --list-tools
python codex-expert-kit/mcp/server.py --call search_expert_knowledge --request-file .\cek-ta-search-request.json
```

`cek-ta-search-request.json` 示例：

```json
{
  "request_id": "local_check_001",
  "query": "lookahead bias",
  "filters": {
    "tree_node_id": "kt.backtest.bias"
  }
}
```

业务项目中，Codex 的调用流程应该是：

```text
用户任务
  -> 读取业务项目 AGENTS.md
  -> 读取业务项目事实 docs/*
  -> 判断需要哪些 CEK-TA domain/skill
  -> 通过 MCP 检索专业知识
  -> 检查知识来源和冲突状态
  -> 输出实现、审计或修改建议
```

## 外部项目健康检查

业务项目接入后，必须使用健康检查模板进行自检：

```text
codex-expert-kit/templates/external_project_healthcheck.md
```

健康检查覆盖：

```text
CEK-TA 路径
项目事实边界
运行模式
字段映射
CEK-TA tool 权限
知识查询范围
MCP 配置
倒灌准备情况
验证与回滚
```

检查结果：

```text
pass: 必填项完整，权限边界清楚。
warn: 可继续使用，但存在缺失的可选资料或非实盘细节。
fail: 项目事实、密钥、账户、实盘权限或 approved 写入边界不安全。
```

如果结果是 `fail`，Codex 不能使用 CEK-TA 对该项目做交易相关修改，只能先修复接入问题。

## 其他项目如何反哺 CEK-TA

业务项目可以把项目中发现的专业经验贡献给 CEK-TA，但不能直接写入通用知识库。

推荐流程：

```text
业务项目发现专业经验
  -> 在业务项目创建 Contribution From Project
  -> 脱敏和去项目私有化
  -> 补充来源与证据
  -> 标注适用范围
  -> 检查与 CEK-TA 现有知识是否冲突
  -> 提交到 CEK-TA contributions/proposed/
  -> CEK-TA 审计通过后入库
```

倒灌入口模板：

```text
codex-expert-kit/templates/contribution_from_project.md
```

倒灌初始状态必须是：

```text
proposed
```

禁止：

```text
直接写入 CEK-TA approved 知识
跳过脱敏
跳过来源
跳过冲突检查
把业务项目私有字段提升成通用规则
```

可以反哺：

```text
回测偏差案例
模拟盘撮合问题
实盘事故经验
交易 bad case 标签
策略审计模式
官方规则更新
LLM/RAG 工程经验
```

不能反哺：

```text
密钥、账户、token
未脱敏订单和账户数据
业务项目私有字段
只对单个项目成立的临时配置
无来源的主观结论
```

详细规范见：

[知识倒灌与反哺规范.md](./知识倒灌与反哺规范.md)

## 接入验收

其他项目完成接入后，必须能通过以下检查：

```text
1. Codex 能说明当前业务项目事实来自哪里。
2. Codex 能说明 CEK-TA 支持层路径在哪里。
3. Codex 能区分项目事实和通用知识。
4. Codex 在给出专业结论时能引用来源或说明需要联网检索。
5. Codex 发现冲突理论时不会直接合并，而是标注适用边界。
6. Codex 修改交易逻辑时能输出输入、输出、影响模块、验证指标和回滚方式。
7. 如果业务项目反哺知识，Codex 能先生成倒灌任务卡，而不是直接写入 CEK-TA。
```

## 运行时接入 DoD

```text
1. 业务项目 AGENTS.md 存在，并指向 CEK-TA。
2. docs/project_adapter.md 存在，并覆盖项目身份、运行模式、数据源、字段映射、风险边界。
3. allowed_cek_ta_tools 只包含只读工具。
4. blocked_cek_ta_tools 明确阻断密钥、账户、下单、approved 写入。
5. healthcheck_result 不是 fail。
6. knowledge_query_scope 要求来源、冲突和适用边界。
7. contribution_entrypoint 指向 contributions/proposed/。
8. 回灌任务不能绕过 proposed。
```
