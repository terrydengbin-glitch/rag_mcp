# CEK-TA 任务需求清单

> 项目管理入口：见 [index_tasks.md](./index_tasks.md)。

本文把《需求框架.md》拆成可执行、可验收、可追踪的任务需求。

## 总目标

这套方案的目标，是让 Codex 在任何交易项目里，都能像一个懂量化、懂 K 线、懂回测、懂模拟盘、懂实盘风控、懂 LLM 训练的工程合伙人一样工作；项目只提供事实，能力由专家包复用。

## 项目定位

本项目是支持层项目，用于为其他项目开发提供专业知识库、专家工作流、RAG/MCP 检索能力和 Vue3 审计界面。

硬性要求：

```text
1. 每个专业知识细节都必须通过 Codex 联网搜索专业资料、官方文档、论文、权威数据或高质量工程资料后入库。
2. 每条知识必须规范归类，并记录来源、版本、适用范围、时效性、置信度和审计状态。
3. 不允许存在互相矛盾且未标注适用边界的理论规则。
4. 存在理论差异时，必须按市场、周期、数据粒度、假设条件和证据等级消解。
5. 必须有 Vue3 知识审计界面，用于查看知识、来源、冲突、版本和 Codex 采集任务记录。
```

## 任务链路

## 验收总门槛

```text
1. 每个任务都有明确交付物路径
2. 每个交付物能对应回《需求框架.md》中的章节
3. 每个 Skill 都能被 Codex 独立加载并执行
4. 每个项目只需要补 Project Adapter 和项目事实
5. 所有交易策略改动都能说明输入、输出、影响模块、验证指标、回滚方式
```
